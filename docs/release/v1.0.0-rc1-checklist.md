## Known limitations

- RuntimeBridge is read-only. It intentionally does not expose property
  setters, arbitrary method invocation, reflection execution, or business
  objects.
- RuntimeBridge currently supports `net48` and `net8.0-windows`; a `net472`
  application cannot reference it without a compatibility experiment or a
  temporary retargeted copy. This is a validation limitation, not a license to
  modify NGUS2.
- UIA actions that simulate desktop input require a visible desktop. Headless
  mode should use UIA patterns such as `set_value` where available.
- Runtime and diagnostics snapshots are bounded. Callers must honor
  `maxDepth`, `maxNodes`, row/count limits, and `truncated` flags.
- AntdUI semantic coverage is provider/version-sensitive and returns warnings
  or per-scope errors when an internal cache is unavailable.
- For old-style projects with direct `bin\Release` output, renderer dependency
  discovery now prefers the most complete assembly directory and includes both
  DLL and EXE outputs. This does not make a `net472` application bridge-capable.
- UIA `find_element` performs a bounded desktop-level query. For nested custom
  controls, call `get_element_tree` first and use its cached IDs for actions.
- Windows 10 versus Windows 11 and standalone .NET 10 execution are not
  independently verified; `windows-latest` CI is the authoritative Windows
  check.
- `bridgeInstanceId` is optional for compatibility. Supplying it is recommended
  for stale-reference protection after a target process restarts.
